# Runtime-specific ASR sidecars with explicit prewarm

JustSay will keep one user-facing profile model while treating deployment mode as a separate concern: each managed or remote sidecar serves exactly one ASR runtime family, sidecar health reports authoritative runtime identity, and heavyweight Qwen model loading stays outside hidden `health-check` or session-start side effects. Explicit `prewarm` remains part of the protocol, while hosted Qwen deployments may also use a startup prewarm policy that warms in the background and reports `warming` readiness until the runtime is fully loaded. We chose this shape because it preserves the existing product model (`local-fast` / `local-accurate`), keeps remote mismatch detection understandable, and avoids turning a generic “local service” endpoint into an implicit multi-runtime broker.
