# Session state machines dispatch explicit transition effects

JustSay keeps pure transition tables in `src/core/session/session-machine.ts` and makes coordinators authoritative consumers of both the next status and the transition effect. Each coordinator runs a serial dispatch loop: apply the transition, execute exactly one effect without nesting further dispatches inside the effect runner, then enqueue any follow-up control events returned by that effect. Failures return an explicit `{ failed }` result that enqueues `FAILED`, and terminal paths return an explicit `RESET` (with `clearError` when the operator should retain a recoverable error banner). Meeting follows the same dispatch pattern as PTT. Recovery completion is applied inside `performRecovery` after the engine signals ready, because the recovery wait crosses an async engine callback that cannot safely enqueue follow-up events into the parent dispatch loop.

We rejected nesting `dispatch` inside `runEffect` because it hides control flow, and rejected auto-enqueueing `RESET` from the loop because explicit follow-ups keep tests and logs aligned with the state machine. Data-plane events such as `audio-chunk` stay outside the loop so the machine does not grow self-loop effects for every streaming frame. Both coordinators share the serial dispatch loop in `src/core/session/session-dispatch.ts`.
