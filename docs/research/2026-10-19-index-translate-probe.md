# 2026-10-19 Index-Translate-2B 和识别同时跑

实验分支：`experiment/index-translate-2b`。机器：RTX 4060 Ti，16380 MiB。识别是现有 `Qwen/Qwen3-ASR-1.7B` sidecar，`gpu_memory_utilization=0.55`，`max_model_len=8192`。翻译是 `IndexTeam/Index-Translate-2B-GGUF` 的 `Q4_K_M`（1,312,164,352 字节），llama.cpp `b11721` 的 `llama-server`，上下文 4096，`--reasoning off`，Flash Attention 开。产品代码没有改。

这是 8 句对齐样本，不是基准。分数不能和模型卡上的 COMET 比较。识别换成 SenseVoice 之后的对照写在 [SenseVoice 加两套翻译](2026-10-19-sensevoice-mt-probe.md)。

## 结论

**两套可以同时留在这张卡上。** 桌面占用约 3.6 GiB 时，识别加翻译的显存峰值是 12849 MiB，还剩约 3.5 GiB。翻译单独大约 1.7 GiB。一句译文的请求在 0.4 秒以内，48 次官方提示和 48 次当前客户端提示都没有空结果，也没有思考标签。

译文本身读得通，尤其是译入英语。字符 chrF 偏低，是因为对照句是 FLEURS 另一种语言的平行说法，不是这句输入的参考译文。日译中在这个指标上最弱，但抽查仍是同义改写。当前英文 system 提示，在服务器已经关掉思考的前提下，和官方中文提示几乎一样可用。

## 资源

采样是 Windows `nvidia-smi` 的整卡 `memory.used`。实验开始前、两个模型都没加载时是 3684 MiB。

| 时刻 | 已用 MiB |
|---|---:|
| 两个模型都就绪，翻译请求之前 | 12801 |
| 识别回放和翻译重叠的 165 次采样 | 12802–12849 |
| 停掉 `llama-server` 之后，识别容器还在 | 11114 |
| 再停掉识别容器 | 3575 |

由此估出：识别实际约 7539 MiB（11114 − 3575），低于 0.55 的预留上限 9009 MiB；翻译约 1703 MiB（12817 − 11114）。重叠时 GPU 利用率最高到 100%，显存只比空闲多了几十 MiB。没有 OOM。

`llama-server` 加载时忽略了 `blk.24` 的一组 nextn 张量。冒烟句「今日はいい天気です。」得到 “It's a nice day today.”，随后的批量请求也完成了。

## 译文

8 个 `sentence_id`（1731、1821、1931、1758、1818、1965、1694、1695）在日语、英语、中文 FLEURS 测试集里都有，时长都在 6–16 秒。六个方向各 8 句。官方提示是一条中文用户消息，并带 `enable_thinking: false` 和 `max_tokens: 256`。当前客户端提示是仓库里的英文 system 加 `Source language` / `Target language` / `Text`，temperature 0，不带思考字段，也不带 `max_tokens`。

chrF 是自写的字符 1–6 gram、beta = 2，对照的是另一种语言的 FLEURS `raw_reference`。它惩罚同义改写。

| 提示 | 条数 | 空结果 | 思考标签 | 超过 10 秒 | chrF | 延迟均值 / 最大 |
|---|---:|---:|---:|---:|---:|---:|
| 官方 | 48 | 0 | 0 | 0 | 0.415 | 237 / 394 ms |
| 当前客户端 | 48 | 0 | 0 | 0 | 0.403 | 244 / 363 ms |

48 对里有 36 对两种提示的输出不同。各有 1 条和对照句逐字相同，是同一句英译日。

官方提示按方向：

| 方向 | chrF | 延迟均值 |
|---|---:|---:|
| 日→英 | 0.584 | 259 ms |
| 中→英 | 0.593 | 235 ms |
| 英→日 | 0.474 | 257 ms |
| 英→中 | 0.338 | 215 ms |
| 中→日 | 0.279 | 249 ms |
| 日→中 | 0.223 | 207 ms |

同一句的官方输出可以看出 chrF 在惩罚什么：

- 日→英：输入「群島や湖では、必ずしもヨットは必要ありません。」输出 “On islands and lakes, a yacht is not always necessary.” 对照是 “In the archipelagos and lakes you do not necessarily need a yacht.” chrF 0.42。
- 日→中：输出「在群岛或湖泊上，不一定需要游艇。」对照是「在群岛和湖泊之中，游艇并不是必需的。」chrF 0.16。意思在，用词不同。
- 英→日：输出和日语 FLEURS 句逐字相同。8 句里只有这一条是这样，不能当成模型只会抄训练集。

## 识别之后再翻译

4 句 × 3 种语言，按键模式，实时节奏，语言参数按 `ja` / `en` / `zh` 送进 sidecar。12 次里有 7 次没有提交文本。这 7 条整段 RMS 都低于现有的 0.01 静音门（0.0004–0.0070）。有提交的 5 条都高于这个门。空提交是识别门，不是翻译失败。

有提交的 5 条用官方提示翻译，chrF 均值 0.599。其中日语「脳病理と行動の相関関係は、科学者たちの研究を裏付けるものです。」被识别成同一句，再译成 “The correlation between brain pathology and behavior supports the research of scientists.” 提交后的翻译延迟大约 150–250 ms，和上表同一量级。

## 还不能当成默认

- 服务器是用 `--reasoning off` 启动的。这次没有证明思考开着时，当前客户端仍然安全。
- 8 句不能代表会议、混说或专名。日译中需要更大的一份材料，而且要用直接参考译文，不能只用 FLEURS 平行句的 chrF。
- 上下文按模型配置会到 262144。这次把它限制在 4096。按满上下文分配 KV，1.7 GiB 这个占用不再成立。
